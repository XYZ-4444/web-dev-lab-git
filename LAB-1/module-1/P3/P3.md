# Feature-Branch Git Workflow

A simple portfolio page (`P3.html` + `P3.css`) built using the feature-branch workflow in Git and GitHub.

## What is a feature branch?

A feature branch is a separate copy of your code where you build one new thing (a feature or a fix) without touching `main`. When it is finished and tested, you merge it back into `main`.

**Why use it?**
- `main` always stays clean and working
- Easy to review changes before merging
- Easy to undo or delete if something goes wrong

## Steps I followed

1. **Start from an updated main**
   ```bash
   git checkout main
   git pull origin main
   ```

2. **Create a feature branch**
   ```bash
   git checkout -b feature/p3
   ```

3. **Make changes** (create `P3.html`, `P3.css`, `P3.md`) and check the status
   ```bash
   git status
   ```

4. **Stage and commit**
   ```bash
   git add .
   git commit -m "Add P3 portfolio page with navbar and project cards"
   ```

5. **Push the branch to GitHub**
   ```bash
   git push -u origin feature/p3-portfolio
   ```

6. **Open a Pull Request** on GitHub (feature branch into `main`), review the changes, then click **Merge pull request**.

7. **Update local main and clean up**
   ```bash
   git checkout main
   git pull origin main
   git branch -d feature/p3-portfolio
   ```

## Useful commands

| Command | What it does |
|---|---|
| `git branch` | List local branches |
| `git checkout -b name` | Create and switch to a new branch |
| `git switch name` | Switch to an existing branch |
| `git merge name` | Merge a branch into the current one |
| `git branch -d name` | Delete a merged branch |
| `git log --oneline` | Show a short commit history |

## Branch naming tips

- `feature/navbar`
- `fix/broken-link`
- `docs/update-readme`
