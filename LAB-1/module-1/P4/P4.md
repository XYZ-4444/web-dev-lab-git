# P4: GitHub README and Version Tags

## Aim

To create a README file for a GitHub repository and mark a stable release using a Git version tag.

## What is a README?

A `README.md` is the front page of a repository. GitHub shows it automatically on the repository's main page. It explains what the project is, how to run it, and what is inside.

A good README has:
- Project title and short description
- Project structure
- How to run it
- Technologies used
- Author name

## What is a version tag?

A tag is a permanent label on a specific commit. It is used to mark a release point such as `v1.0.0`.

**Annotated tag** (used in this practical): stores the author, date, and a message.
**Lightweight tag**: just a name pointing to a commit.

## Version format

`v1.0.0` follows `MAJOR.MINOR.PATCH`:
- **MAJOR**: big changes that break old behavior
- **MINOR**: new features added
- **PATCH**: small bug fixes

## Steps

1. Create the README file
   ```bash
   touch README.md
   ```

2. Write the project details in it, then commit
   ```bash
   git add README.md
   git commit -m "Add project README"
   ```

3. Create an annotated tag
   ```bash
   git tag -a v1.0.0 -m "First stable release"
   ```

4. Check the tag
   ```bash
   git tag
   git show v1.0.0
   ```

5. Push the commit and the tag to GitHub
   ```bash
   git push origin main
   git push origin v1.0.0
   ```

## Useful commands

| Command | What it does |
|---|---|
| `git tag` | List all tags |
| `git tag -a v1.0.0 -m "message"` | Create an annotated tag |
| `git show v1.0.0` | Show tag details |
| `git push origin v1.0.0` | Push one tag to GitHub |
| `git push origin --tags` | Push all tags |
| `git tag -d v1.0.0` | Delete a tag locally |

## Result

The repository now has a README on its main page and a `v1.0.0` release tag, visible under **Releases / Tags** on GitHub.

## What I learned

- How to write a README using Markdown
- The difference between annotated and lightweight tags
- How version numbers work (MAJOR.MINOR.PATCH)
- How to push tags to GitHub
